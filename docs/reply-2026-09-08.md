### 1.4 공개하지 않은 파일

각 실행 폴더의 `train_batch*.jpg` · `val_batch*.jpg` · `labels.jpg` 는 학습에 쓰인
**현장 배근 사진이 그대로 렌더링된 이미지**입니다. 원본 데이터셋(`data/`)을 공개하지
않는 것과 같은 이유로 제외했습니다. 검토에 필요하시면 별도 협의 후 전달하겠습니다.

### 1.5 `splice_n_cpu` · `helper_round2_v2` · `tile_scorer` 에 대하여

이 세 폴더는 **본 저장소의 실행이 아닙니다.** 개발 PC 전체를 검색했으나 해당 이름의
디렉터리는 존재하지 않았습니다. 파일럿 보고서 표 4의 다섯 실행은 위 1.2의
`splice_*` 계열이며, 확인하신 환경에서 별도로 수행된 실험으로 보입니다.
따라서 "`splice_n_cpu` 의 batch 16" 은 본 파일럿의 설정이 아닙니다.

## 2. 질의 2 — 확정 하이퍼파라미터

다섯 실행은 `model` · `batch` · `imgsz` 세 값만 다르고 나머지는 전부 동일합니다.
`args.yaml` 을 서로 비교하면 확인됩니다. 아래는 배포 모델 `splice_l` 기준입니다.

### 2.1 확정값

| 항목 | 값 |
|---|---|
| 사전학습 가중치 | `yolo26l.pt` — **COCO 사전학습**, `pretrained: true` |
| epochs / patience | 200 / 50 |
| batch / imgsz | **4** / 640 |
| optimizer | **AdamW** (설정은 `auto`) |
| lr0 / lrf | **0.001667** / 0.01, 선형 감쇠 |
| momentum | **0.9** |
| weight_decay | 0.0005 |
| warmup | epochs 3.0 · momentum 0.8 · **bias_lr 0.0** |
| nbs (유효 배치) | 64 |
| loss 가중치 | box 7.5 · cls 0.5 · dfl 1.5 |
| 기타 | amp true · seed 0 · deterministic true · cos_lr false · close_mosaic 10 |

### 2.2 정정 1 — batch 는 4입니다

`training-guide.md` 의 8 은 s 모델 기준 기본값입니다. 실제로는 8GB VRAM 한계에 맞춰
모델·해상도별로 s=8, m=6, **l=4**, m960=3, l960=2 로 낮췄습니다. 성능 비교를 위한
변수가 아니라 메모리 제약입니다. `nbs=64` 정규화 때문에 옵티마이저가 보는 유효 배치는
다섯 실행이 동일합니다.

### 2.3 정정 2 — optimizer 는 SGD 가 아니라 AdamW 입니다

`args.yaml` 에 기록된 `optimizer: auto` · `lr0: 0.01` · `momentum: 0.937` 은
**설정값이며 실제 사용값이 아닙니다.** Ultralytics 는 `auto` 인 경우 학습 시작 시
이 값들을 무시하고 다시 결정합니다 (`ultralytics/engine/trainer.py:1105`, v8.4.129).

```
iterations = ceil(train_set / max(batch, nbs)) x epochs
           = ceil(255 / max(4, 64)) x 200 = 4 x 200 = 800

800 <= 10000  ->  AdamW
                  lr0 = round(0.002 x 5 / (4 + nc), 6)    # nc = 2
                      = round(0.002 x 5 / 6, 6) = 0.001667
                  momentum = 0.9
                  warmup_bias_lr = 0.0  (forced)
```

여기서 `train_set` 은 학습 타일 수(255), `nc` 는 클래스 수(2)입니다. batch 가 2~8 로
달라도 `max(batch, 64) = 64` 라 iterations 가 800 으로 같습니다. 따라서 **다섯 실행 모두
AdamW(lr0 0.001667, momentum 0.9)** 이며, `warmup_bias_lr` 도 설정값 0.1 이 아니라
0.0 으로 강제됩니다.

이 값은 로그가 아니라 산출 데이터로도 검증됩니다. `results.csv` 마지막 에폭의 학습률이
`2.49217e-05` 인데, 선형 감쇠식에 lr0 = 0.001667 을 대입하면

```
0.001667 x ((1 - 199/200) x (1 - 0.01) + 0.01) = 0.001667 x 0.01495 = 2.492e-05
```

으로 일치합니다. lr0 이 0.01 이었다면 `1.495e-04` 가 기록됐어야 합니다.

### 2.4 조기종료로 실제 종료된 에폭 — 조기종료는 발동하지 않았습니다

`patience: 50` 으로 설정했으나 **다섯 실행 모두 200 에폭을 완주**했습니다. 각
`results.csv` 의 데이터 행이 200 개인 것으로 확인됩니다.

`best.pt` 가 배포 모델 기준 179 에폭인 것은 조기종료 때문이 아니라, Ultralytics 가
fitness(`0.1 x mAP50 + 0.9 x mAP50-95`) 최댓값 에폭의 가중치를 `best.pt` 로 저장하기
때문입니다.

### 2.5 증강 최종값

| 항목 | 값 | 항목 | 값 |
|---|---|---|---|
| hsv_h / hsv_s / hsv_v | 0.015 / 0.7 / 0.4 | mosaic | 1.0 (마지막 10 에폭 해제) |
| degrees (회전) | 15.0 | mixup | 0.1 |
| translate / scale | 0.1 / 0.5 | cutmix / copy_paste | 0.0 / 0.0 |
| shear / perspective | 0.0 / 0.0 | auto_augment | randaugment |
| **flipud (상하반전)** | **0.0 — 사용 안 함** | erasing | 0.2 |
| fliplr (좌우반전) | 0.5 | bgr | 0.0 |

상하반전을 배제한 이유는 배근 사진에서 상하 방향이 의미를 갖기 때문입니다. 좌우반전은
유지했습니다. 문의하신 목록(HSV · 회전 15° · 모자이크 · erasing 0.2 · 상하반전 금지)과
전부 일치합니다.

## 3. 정정 사항 — 배포 모델 정밀도

이번 확인 과정에서 `best.pt` 로 검증을 다시 수행한 결과, **lap_splice 정밀도가
0.872 가 아니라 0.868** 이었습니다. 파일럿 보고서 표 4의 값은 학습 종료 시점의 검증
출력에서 옮긴 것으로 보이며, 아래가 배포 가중치를 독립적으로 재측정한 값입니다.
저장소 README 도 이 값으로 수정했습니다.

검증셋 54 타일 / 528 인스턴스 (lap_splice 132, rebar 396):

| 클래스 | P | R | mAP50 | mAP50-95 |
|---|---|---|---|---|
| **lap_splice** | **0.868** | 0.818 | **0.861** | 0.698 |
| rebar | 0.857 | 0.678 | 0.796 | 0.576 |
| all | 0.862 | 0.748 | 0.828 | 0.637 |

mAP50 0.861 과 재현율 0.818 은 보고서 값과 동일합니다.

재현 명령:

```bash
python -c "from ultralytics import YOLO; YOLO('yolo26l-640-best.pt').val(data='data/dataset.yaml', imgsz=640, split='val')"
```
