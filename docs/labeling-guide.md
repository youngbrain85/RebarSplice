# 철근 겹침이음 — 라벨링

**클래스 1개**: `lap_splice` · **박스**: 축정렬 바운딩박스

---

## 규칙 — 이게 전부다

> **이음부처럼 보이면 박스를 친다.**
> 철근 두 가닥이 나란히 겹쳐 있는 부분을 감싼다.

애매하면 그냥 판단해서 넘어간다. 자기 판단을 믿고 **속도를 유지한다.**

경계가 몇 cm 어긋나는 건 상관없다. 평가를 `mAP50` 으로 하기 때문에 IoU 0.5 만
넘으면 정답이다.

**안 보이는 건 안 그린다** — 너무 작거나, 흐리거나, 대부분 가려져 있으면 넘어간다.

결속선 종류, 이음 길이, 철근 지름 — **전부 신경 쓰지 않는다.** 지금 만드는 건
"여기가 이음부다" 만 말하는 모델이다.

---

# 순서대로

## 1. Roboflow 계정 · 프로젝트

1. [roboflow.com](https://roboflow.com) 가입 (무료 플랜)
2. **Create New Project**
3. 이렇게 채운다:

| 칸 | 값 |
|---|---|
| Project Name | `rebar-splice` |
| Project Type | **Object Detection** |
| Annotation Group | `splice` |
| License | 아무거나 (공개 저장소라 상관없음) |

> 무료 플랜은 데이터셋이 **공개**된다. 이 프로젝트는 공개 전제라 문제없다.
> 현장 사진에 사람 얼굴이나 도면 정보가 찍혔으면 그 장만 빼라.

---

## 2. 사진 올리기

**Upload** → 사진을 통째로 끌어다 놓는다.

### 올리기 전에 반드시 할 것 — 파일명

파일명 앞에 **촬영 장소**를 붙인다.

```
siteA_001.jpg   siteA_002.jpg   ...
siteB_001.jpg   ...
siteC_001.jpg   ...
```

아이폰 기본 이름(`IMG_1234.jpg`)으로 올리면 **학습/검증 누수 검사를 못 한다.**
이 검사는 나중에 손으로 되돌리기 어려우니 지금 해 둔다.

일괄 변경 (PowerShell, 해당 폴더에서):

```
Get-ChildItem *.jpg | ForEach-Object { Rename-Item $_ "siteA_$($_.Name)" }
```

### 해상도는 줄이지 않는다

**아이폰 원본 그대로 올린다.** Roboflow 가 알아서 처리한다.
미리 줄이면 나중에 다른 입력 크기로 다시 뽑을 수 없다.

### 이음 없는 사진도 같이 올린다

전체의 **20~30%**. 이걸 빼먹는 게 이 도메인 최빈 실패다 (→ 5번에서 다시 설명).

---

## 3. 박스 그리기

**Annotate** → 사진을 누르면 편집기가 열린다.

### 조작

| 키 | 동작 |
|---|---|
| `B` | 박스 도구 |
| 드래그 | 박스 그리기 |
| `Enter` | 저장하고 다음 장 |
| `D` / `→` | 다음 장 |
| `A` / `←` | 이전 장 |
| `Delete` | 선택한 박스 삭제 |
| `Ctrl` + `Z` | 되돌리기 |

첫 박스를 그리면 클래스 이름을 묻는다. **`lap_splice`** 라고 치면 그다음부터는
자동으로 같은 클래스가 붙는다.

### 어떻게 그리나

겹쳐 있는 **두 가닥이 나란한 구간 전체**를 감싼다. 겹침이 시작되는 곳부터
끝나는 곳까지.

- 한 사진에 이음이 여러 개면 **각각 따로** 박스를 친다
- 박스끼리 겹쳐도 된다
- 세로로 긴 박스가 되는 게 정상이다 (벽체 수직철근)

### 속도

한 장에 **10~20초**를 넘기지 마라. 100장이면 30분~1시간이면 끝난다.
한 장에서 1분씩 고민하고 있으면 규칙이 잘못된 것이다 — 그냥 판단하고 넘어간다.

---

## 4. 이음 없는 사진 — 박스 0개로 저장

이음이 없는 사진은 **아무것도 안 그리고** 그냥 다음 장으로 넘긴다.

Roboflow 는 이걸 **Null / Unannotated** 로 표시한다. **삭제하지 마라.**
데이터셋에 그대로 포함되어야 한다.

내보낼 때 Roboflow 가 "annotation 없는 이미지를 포함할까?" 를 물으면
**반드시 포함(include)** 을 고른다.

---

## 5. 왜 이음 없는 사진이 필요한가

이음 있는 사진만 학습시키면 모델이 배우는 규칙은 이렇게 된다:

> "철근이 보인다 → 이음이다"

배근 사진 전부에 박스를 치게 되고 검출기로서 쓸모가 없어진다.
**"철근은 있는데 이음은 없는" 상태**를 보여줘야 둘을 구분한다.

`check_dataset.py` 가 이 비율을 검사해서 20% 미만이면 경고, 10% 미만이면
문제로 잡는다.

---

## 6. 학습 / 검증 나누기 — 여기서 실수하면 전부 무의미해진다

**Roboflow 기본값(무작위 80:20)을 쓰지 마라.**

```
❌ 무작위 80:20
✅ 현장 A·B = 학습  /  현장 C = 검증
```

같은 이음부를 찍은 사진이 학습과 검증에 나뉘어 들어가면, 모델이 검증셋의
그 이음부를 **이미 본 것**이다. 점수가 가짜로 높게 나오고 현장에서 무너진다.

### Roboflow 에서 하는 법

Annotate 화면에서 사진을 고르고 → 우클릭(또는 상단 메뉴) → **Move to Train / Valid**

`siteC_` 로 시작하는 사진을 전부 골라 **Valid** 로 보낸다. 나머지는 Train.

검색창에 `siteC` 를 치면 그 장소 사진만 걸러진다. 전체 선택 후 한 번에 옮긴다.

`check_dataset.py` 가 이걸 검사한다:

```
[문제] 학습과 검증에 같은 장소가 있다: ['siteA'].
       같은 이음부를 찍은 사진이 양쪽에 들어가면 검증 점수가 가짜로 높게 나온다
```

## 7. 버전 만들기 (Generate)

**Generate** → 두 가지만 신경 쓴다.

### Preprocessing

| 항목 | 설정 |
|---|---|
| Auto-Orient | **켠다** (아이폰 EXIF 회전 문제를 없앤다) |
| Resize | **Stretch to 640×640** 또는 끔 — 어느 쪽이든 된다 |

### Augmentation — **전부 끈다**

`train.py` 가 이미 증강한다 (회전·명암·좌우반전·모자이크·가림).
Roboflow 에서 또 걸면 **이중으로 걸려서 오히려 나빠진다.**

증강 배수(`3x` 같은 것)도 **1x** 로 둔다.

---

## 8. 내보내기

**Export Dataset** → **YOLOv8** → **Download zip to computer**

> **"YOLO26 을 쓰는데 왜 YOLOv8 포맷?"**
> YOLOv8 은 모델 버전이 아니라 **데이터셋 형식** 이름이다. Ultralytics 는
> v5 부터 v26 까지 라벨 형식이 같다. 목록에 v11 이 있어도 나오는 파일은 동일하다.

압축을 `data/` 에 푼다:

```
data/
  data.yaml
  train/images/   train/labels/
  valid/images/   valid/labels/
```

**`data.yaml` 은 고치지 않아도 된다.** 안의 `../` 경로를 Ultralytics 가 알아서
처리한다 (`ultralytics/data/utils.py:606`, 실측 확인).

라벨 파일은 한 줄에 박스 하나, 값은 0~1 로 정규화되어 있다:

```
0 0.512340 0.433210 0.087500 0.245800
↑ 클래스   ↑ 중심x   ↑ 중심y   ↑ 폭     ↑ 높이
```

네거티브 사진의 `.txt` 는 **빈 파일**이거나 아예 없다. 정상이다.

## 다시 확인할 세 가지

라벨 규칙은 느슨해도 되지만, 아래 셋은 어기면 **100장이 통째로 쓸모없어진다.**

1. **이음 없는 사진 20~30%** — 박스 0개로 포함 (빼는 게 아니다)
2. **서로 다른 이음부 30개소 이상** — 같은 자리 연사 30장은 1장으로 친다
   섞을 것: 거리(0.3m/1m/2m) · 각도 · 조명(맑음/그늘/역광) · 배근 밀도 · 녹·흙
3. **학습/검증을 촬영 장소 단위로** — 무작위 분할 금지

---

## 100장으로 판단할 것

정확도를 재는 게 아니다. 100장으로는 못 잰다. 볼 것은 셋:

1. 학습 손실이 내려가는가
2. 검증셋에서 뭐라도 잡는가
3. 오검출이 **어디서** 나는가 — 패턴이 보이면 그때 규칙을 추가한다

`mAP50` **0.3~0.5** 면 정상이다. **0 에 가까우면** 그때 라벨 정의를 다시 본다.
